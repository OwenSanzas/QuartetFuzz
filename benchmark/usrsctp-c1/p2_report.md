## target: usrsctp_conninput

### P2.1 Init Sequence
**Claim:** Before any call to `usrsctp_conninput`, the embedder must (1) call `usrsctp_init()` (global stack init, registers the `conn_output` callback used for AF_CONN sockets), (2) call `usrsctp_register_address()` for the opaque address token that will be used both as the socket's bound address and as the `addr` argument to `usrsctp_conninput`, (3) create a socket with `usrsctp_socket()`, (4) `usrsctp_bind()` it to a `sockaddr_conn` using that same address token, and (5) either `usrsctp_connect()` (client path) or `usrsctp_listen()`/`usrsctp_accept()` (server path) so that an association/listening PCB exists for `sctp_findassociation_addr()` (inside `sctp_common_input_processing`) to match against. Calling `usrsctp_conninput` before `usrsctp_init`/`usrsctp_socket` is architecturally pointless: there is no PCB/association for the injected packet to match, so it is treated as an out-of-the-blue (OOTB) packet (may still trigger OOTB ABORT/INIT paths but does not exercise association state machines).
**Evidence:**
> usrsctplib/user_socket.c:137-156 (fuzzer/fuzzer_connect.c:137-156) `initialize_fuzzer()`: `usrsctp_init(0, conn_output, NULL); usrsctp_enable_crc32c_offload(); usrsctp_register_address((void *)1); usrsctp_sysctl_set_sctp_pktdrop_enable(1); usrsctp_sysctl_set_sctp_nrsack_enable(1);`
> fuzzer/fuzzer_connect.c:278-364: `usrsctp_socket(AF_CONN, ...)` → several `usrsctp_setsockopt()` → `usrsctp_bind(socket_client, &sconn...)` → `usrsctp_set_upcall(...)` → `usrsctp_connect(socket_client, &sconn...)`, all **before** the first `usrsctp_conninput()` call at line 374.
> usrsctplib/user_socket.c:1330-1333: `usrsctp_socket()` returns NULL with `errno = EAFNOSUPPORT` if `domain == AF_CONN` and `SCTP_BASE_VAR(conn_output) == NULL`, i.e. `usrsctp_init()` (which sets `conn_output`) must run first.
> usrsctplib/netinet/sctp_input.c:5769: `sctp_findassociation_addr(m, offset, src, dst, sh, ch, &inp, &net, vrf_id)` is how `sctp_common_input_processing` (reached from `usrsctp_conninput`) locates the inpcb/association — requires a prior `usrsctp_bind`/`usrsctp_connect`/`usrsctp_listen` to have created it.

### P2.2 Parameter Construction
**Claim:** `usrsctp_conninput(void *addr, const void *buffer, size_t length, uint8_t ecn_bits)`: `addr` is an opaque, embedder-chosen pointer-sized token (not dereferenced as a real address; used only as `sconn_addr` for AF_CONN sockaddr matching) and must equal the token used in `usrsctp_register_address`/`usrsctp_bind`/`usrsctp_connect`. `buffer`/`length` is attacker-controlled raw SCTP packet bytes (common header + chunk chain); `length` must be at least `sizeof(struct sctphdr)+sizeof(struct sctp_chunkhdr)` (12 bytes) or the function bails out after `m_pullup` fails. `ecn_bits` is passed straight through to `sctp_common_input_processing` as the ECN field from a notional IP header (0 in all observed callers).
**Evidence:**
> usrsctplib/usrsctp.h:1023-1024: `void usrsctp_conninput(void *, const void *, size_t, uint8_t);`
> usrsctplib/user_socket.c:3275-3296: `src.sconn_addr = addr; dst.sconn_addr = addr;` (both src and dst use the same opaque token — this only works because AF_CONN matches by this token plus port).
> usrsctplib/user_socket.c:3311-3317: `offset = sizeof(struct sctphdr) + sizeof(struct sctp_chunkhdr); if (SCTP_BUF_LEN(m) < offset) { if ((m = m_pullup(m, offset)) == NULL) { SCTP_STAT_INCR(sctps_hdrops); return; } }` — minimum 12-byte input enforced before dispatch.
> fuzzer/fuzzer_connect.c:374,384,418,424,445: all calls use `(void *)1` as addr, matching `usrsctp_register_address((void *)1)` (line 150) and the `sconn.sconn_addr = (void *)1` used in `usrsctp_bind`/`usrsctp_connect` (lines 343,361).

### P2.3 Object Lifecycle
**Claim:** `usrsctp_conninput` itself is stateless/non-owning: it allocates its own internal mbuf chain from `buffer`, hands it to `sctp_common_input_processing`, and frees it (`sctp_m_freem(m)`) before returning — it does not take ownership of the caller's `buffer`, and returns `void` (no object, no handle). The life-cycle it participates in is that of the *socket*: create (`usrsctp_socket`) → configure (`usrsctp_setsockopt`, `usrsctp_bind`) → use (`usrsctp_connect`/`usrsctp_listen`+`usrsctp_accept`, then repeated `usrsctp_conninput` calls feeding it inbound packets, `usrsctp_sendv` feeding outbound data) → destroy (`usrsctp_close`), and finally process-wide `usrsctp_finish()`.
**Evidence:**
> usrsctplib/user_socket.c:3297-3333: local `m`/`mm` built from `buffer`, passed by pointer to `sctp_common_input_processing(&m, ...)`, then `if (m) sctp_m_freem(m);` at the end — no handle escapes to caller.
> fuzzer/fuzzer_connect.c:449-450: `usrsctp_close(socket_client);` after all `usrsctp_conninput`/`usrsctp_sendv` calls are done.
> fuzzer/fuzzer_connect.c:452-456 (`#ifdef FUZZ_ALWAYS_INITIALIZE`): optional `usrsctp_finish()` loop only if the stack is re-initialized per iteration (otherwise the harness keeps the socket/init alive across `LLVMFuzzerTestOneInput` invocations via the `static int initialized` guard, line 162/267-270).

### P2.4 Return Value Handling
**Claim:** `usrsctp_conninput` returns `void`; there is no success/failure code to check. Errors inside it (mbuf allocation failure, header pullup failure) are silently absorbed via early `return;` and `SCTP_STAT_INCR` counters (observable only via `usrsctp_get_stat`-style APIs if used, not via a return code). Downstream processing errors (bad checksum, invalid chunk, out-of-bounds parameter) do not propagate back to the caller of `usrsctp_conninput` either — they manifest as the stack internally sending an ABORT/ERROR via the registered `conn_output` callback, or as assertion failures in debug/INVARIANTS builds (the OSS-Fuzz build enables `-Dsctp_invariants=1`, see Build notes).
**Evidence:**
> usrsctplib/user_socket.c:3297-3298: `if ((m = sctp_get_mbuf_for_msg(...)) == NULL) { return; }` — silent early exit, no error returned to caller.
> usrsctplib/user_socket.c:3312-3316: silent early exit on `m_pullup` failure, only `SCTP_STAT_INCR(sctps_hdrops)` recorded.
> usrsctplib/usrsctp.h:1023: declared `void`, confirming no return value exists to check.
> fuzzer/fuzzer_connect.c:374-445: none of the `usrsctp_conninput` call sites check a return value (consistent with `void`).

### P2.5 Cleanup Sequence
**Claim:** Nothing needs to be freed by the caller as a direct result of `usrsctp_conninput` (it manages its own mbuf). What must be freed/closed by the harness, in order, are the resources it created to set up the call: any locally allocated packet buffer (e.g. `fuzz_packet_buffer` in the fuzzer), then the socket via `usrsctp_close(socket_client)`, and finally (only if the stack was initialized fresh) `usrsctp_finish()`. `usrsctp_close` must be called before `usrsctp_finish` (finish checks that the inpcb list is empty).
**Evidence:**
> fuzzer/fuzzer_connect.c:436-450: `fuzz_packet_buffer = malloc(...); ... usrsctp_conninput(...); free(fuzz_packet_buffer); ... usrsctp_close(socket_client);`
> usrsctplib/user_socket.c:2050-2064 (`usrsctp_finish`): `if (!LIST_EMPTY(&SCTP_BASE_INFO(listhead))) { SCTP_INP_INFO_RUNLOCK(); return (-1); }` — fails if sockets/inpcbs (from un-closed `usrsctp_socket`) are still registered, i.e. `usrsctp_close` of all sockets must precede a successful `usrsctp_finish`.

### P2.7 Co-call Constraints
**Claim:** Paired/ordered APIs around the target: (a) `usrsctp_init(...)` must precede `usrsctp_socket(AF_CONN,...)` (enforced by the `EAFNOSUPPORT` check). (b) `usrsctp_socket` → `usrsctp_close` is a required create/destroy pair (every socket created must eventually be closed, verified before `usrsctp_finish` can succeed). (c) `usrsctp_listen` pairs with `usrsctp_accept` (server-side passive open; `usrsctp_accept` only makes sense after `usrsctp_listen` put the socket into `SCTP_SO_ACCEPTCONN` state, checked in `usrsctp_close` at line 1991). (d) `usrsctp_connect` (active open) and `usrsctp_listen`/`usrsctp_accept` (passive open) are alternative, not combined, paths for the *same* socket. (e) `usrsctp_register_address(addr)` should be paired with `usrsctp_deregister_address(addr)` at teardown (not exercised in the fuzzers, which rely on process-exit cleanup, but documented in usrsctp.h:1036).
**Evidence:**
> usrsctplib/user_socket.c:1330-1333: `usrsctp_socket` requires prior `usrsctp_init` (checks `SCTP_BASE_VAR(conn_output)`).
> usrsctplib/user_socket.c:1991: `usrsctp_close` checks `so->so_options & SCTP_SO_ACCEPTCONN` to decide whether to drain the accept queue — this flag is set by `usrsctp_listen`.
> usrsctplib/usrsctp.h:1033,1036: `usrsctp_register_address(void *);` / `usrsctp_deregister_address(void *);` declared as a pair.

### P2.8 Prerequisite State
**Claim:** For `usrsctp_conninput` to reach anything beyond OOTB handling, the following state must already exist: (1) global SCTP base initialized via `usrsctp_init` (`SCTP_BASE_VAR(sctp_pcb_initialized)`); (2) at least one `inpcb` bound to the `(AF_CONN, addr, port)` tuple matching the injected packet's destination port (via `usrsctp_bind`); (3) for the client/COOKIE-ACK and DATA/SACK paths, an association (`stcb`) with a known verification tag — obtained either by having sent an INIT via `usrsctp_connect` (so the harness knows/extracts the association's vtag from the outbound INIT via the `conn_output` callback, as `fuzzer_connect.c` does) or by injecting a fuzzed INIT to the listening socket from `usrsctp_listen`.
**Evidence:**
> fuzzer/fuzzer_connect.c:78-94 (`conn_output`): captures `init_chunk->initiate_tag` into `assoc_vtag` from the *outbound* INIT the stack sends after `usrsctp_connect`, so later `usrsctp_conninput` calls can set `common_header->verification_tag = assoc_vtag` (lines 371,381,416,422,441) to match the real association.
> usrsctplib/netinet/sctp_input.c:5769: `sctp_findassociation_addr(...)` — the actual lookup requiring this state.

### P2.9 Result Usage
**Claim:** `usrsctp_conninput` has no return value to consume directly; its *effects* are consumed in two ways by real callers: (a) data delivered into the socket's receive queue is drained by the application via `usrsctp_recvv()` from inside a registered upcall (`usrsctp_set_upcall`), and (b) any protocol responses the stack needs to send (SACK, ABORT, COOKIE-ECHO, etc.) are emitted synchronously through the `conn_output` callback registered in `usrsctp_init`, which the harness/application must handle (dump, parse for vtag, or loop back).
**Evidence:**
> fuzzer/fuzzer_connect.c:97-133 (`handle_upcall`): `int events = usrsctp_get_events(sock); while (events & SCTP_EVENT_READ) { ... n = usrsctp_recvv(sock, buf, BUFFER_SIZE, ...); ... }` registered via `usrsctp_set_upcall(socket_client, handle_upcall, NULL);` at fuzzer/fuzzer_connect.c:353.
> fuzzer/fuzzer_connect.c:78-93 (`conn_output`): called synchronously by the stack (as the registered `SCTP_BASE_VAR(conn_output)`) whenever `usrsctp_conninput`'s processing produces an outbound packet; it inspects the bytes for an outbound INIT to capture `assoc_vtag` for subsequent `usrsctp_conninput` calls.
> programs/ekr_client.c:88, programs/ekr_peer.c:84, programs/ekr_server.c:89, programs/ekr_loop.c:106/115, programs/ekr_loop_upcall.c:112/121, programs/st_client.c:131: additional real-world callers feeding UDP/socket-received bytes into `usrsctp_conninput`, each paired with a socket already created via `usrsctp_socket`/`usrsctp_bind`/`usrsctp_connect` earlier in the same program.

### P2.10 Behaviour Controls
**Claim:** Several parameters/flags select different processing paths exercised through `usrsctp_conninput`: (a) the injected chunk's `chunk_type` byte selects the `sctp_process_control`/`sctp_process_data` branch (INIT=1, INIT-ACK=2, SACK=3, HEARTBEAT=4/5, ABORT=6, SHUTDOWN=7, ERROR=9, COOKIE-ECHO=10, COOKIE-ACK=11, DATA=0, I-DATA=0x40, FORWARD-TSN=0xC0, ASCONF=0xC1, AUTH=0x0F, RE-CONFIG=0xC6 — per the task description, confirmed by the fuzzer's own packet choice logic). (b) `usrsctp_setsockopt(SCTP_FRAGMENT_INTERLEAVE/SCTP_INTERLEAVING_SUPPORTED)` toggles I-DATA support, changing whether injected DATA (0) or I-DATA (0x40) chunks are expected/valid. (c) `usrsctp_setsockopt(SCTP_ENABLE_STREAM_RESET, ...)` enables stream-reset (RE-CONFIG chunk) handling. (d) `usrsctp_sysctl_set_sctp_nrsack_enable(1)` toggles NR-SACK vs classic SACK chunk type (3) handling. (e) `ecn_bits` argument of `usrsctp_conninput` feeds ECN-handling logic in `sctp_common_input_processing`/core but is always `0` in observed callers. (f) `compute_crc` (derived internally from `SCTP_BASE_VAR(crc32c_offloaded)`, toggled by `usrsctp_enable_crc32c_offload`/`usrsctp_disable_crc32c_offload`) selects whether the packet checksum is validated in software.
**Evidence:**

### P2.11 Input Expectations
**Claim:** `usrsctp_conninput`'s `buffer` is expected to be a raw SCTP packet payload **starting at the common header** (no IP header): 12-byte common header (`src_port` u16, `dest_port` u16, `verification_tag` u32, `checksum` u32) immediately followed by one or more chunks, each beginning with a `struct sctp_chunkhdr` (type u8, flags u8, length u16, big-endian, chunk padded to 4-byte boundary). Minimum enforced size is `sizeof(struct sctphdr)+sizeof(struct sctp_chunkhdr)` = 12+4 = 16? (actually `offset` computed as 12+4=16, but code only guarantees the first `m_pullup(m, offset)` succeeds — i.e. the function requires at least enough bytes for one common header + one chunk header, else it returns silently). There is no explicit upper bound check inside `usrsctp_conninput` itself; `length` is `size_t` and is used to size the mbuf chain via `sctp_get_mbuf_for_msg`. The project's own fuzzers additionally bound `data_size` between 5 and 65535 bytes before constructing packets (an external convention, not enforced by the API).
**Evidence:**
> usrsctplib/user_socket.c:3311: `offset = sizeof(struct sctphdr) + sizeof(struct sctp_chunkhdr);` (12 + 4 = 16 bytes minimum before `m_pullup`).
> usrsctplib/user_socket.c:3312-3317: `if (SCTP_BUF_LEN(m) < offset) { if ((m = m_pullup(m, offset)) == NULL) { SCTP_STAT_INCR(sctps_hdrops); return; } }`
> usrsctplib/user_socket.c:3318-3322: `sh = mtod(m, struct sctphdr *); ch = (struct sctp_chunkhdr *)((caddr_t)sh + sizeof(struct sctphdr)); ... src.sconn_port = sh->src_port; dst.sconn_port = sh->dest_port;` — confirms layout: common header directly followed by first chunk header, no IP header expected.
> fuzzer/fuzzer_connect.c:272-276: `if (data_size < 5 || data_size > 65535) { ... return (0); }` — fuzz-harness-imposed bound, not an API-internal check.
> fuzzer/fuzzer_connect.c:260,436-438: `fuzz_common_header` is a fixed 12-byte template prepended to fuzzed chunk bytes before calling `usrsctp_conninput`, confirming the "common header first" layout convention used by real callers.

## Other entries of this Logic Group (call protocol)

### usrsctp_socket
**Claim:** Creates the `struct socket *` used for all subsequent calls. Requires `usrsctp_init()` to have run first when `domain == AF_CONN` (checks `SCTP_BASE_VAR(conn_output) != NULL`). `receive_cb`/`send_cb`/`sb_threshold`/`ulp_info` may all be NULL/0 (classic blocking-socket mode, used by all fuzzers). Returns `NULL` + `errno` set (`EPROTONOSUPPORT`, `EINVAL`, `EAFNOSUPPORT`) on failure — harness must check for NULL before proceeding. Must eventually be released with `usrsctp_close()`.
**Evidence:**
> usrsctplib/user_socket.c:1312-1347 (definition); usrsctplib/usrsctp.h:908-914 (declaration).
> usrsctplib/user_socket.c:1321-1333: three early-NULL-return error checks (`EPROTONOSUPPORT`, `EINVAL`, `EAFNOSUPPORT`).
> fuzzer/fuzzer_connect.c:278-279: `socket_client = usrsctp_socket(AF_CONN, SOCK_STREAM, IPPROTO_SCTP, NULL, NULL, 0, 0); FUZZER_ASSERT(socket_client != NULL);`
**Combination with target:** Must be called once before the first `usrsctp_setsockopt`/`usrsctp_bind`/`usrsctp_connect`/`usrsctp_listen`, and the returned `struct socket*` is *not* an argument of `usrsctp_conninput` (which only takes the opaque `addr` token) — the link between the two is indirect, via the address/port the socket is bound to.

### usrsctp_bind
**Claim:** Binds the socket to a local `sockaddr_conn` (AF_CONN family, `sconn_port`, `sconn_addr` = the opaque token also passed to `usrsctp_conninput`/`usrsctp_register_address`). Must be called after `usrsctp_socket`. Returns 0 on success, -1 + errno on failure; harness should assert success before proceeding to connect/listen.
**Evidence:**
> usrsctplib/user_socket.c:1464 (definition); usrsctplib/usrsctp.h:976-978 (declaration).
> fuzzer/fuzzer_connect.c:337-346: builds `struct sockaddr_conn sconn` with `sconn_family=AF_CONN`, `sconn_port=htons(5000)`, `sconn_addr=(void*)1`, then `result = usrsctp_bind(socket_client, (struct sockaddr *)&sconn, sizeof(struct sockaddr_conn)); FUZZER_ASSERT(result == 0);`
**Combination with target:** The `(addr, port)` pair bound here is exactly what `sctp_findassociation_addr` (reached from `usrsctp_conninput`) must match against the injected packet's destination port and `addr` token for the packet to be routed to this socket/association rather than treated as OOTB.

### usrsctp_connect
**Claim:** Initiates an active association (sends an outbound INIT through the registered `conn_output` callback). Must be called after `usrsctp_socket`+`usrsctp_bind`. Takes a peer `sockaddr_conn`. Returns 0 on immediate success or -1 with `errno == EINPROGRESS` for non-blocking sockets (the common case in fuzzers, since `usrsctp_set_non_blocking` is typically set). Internally calls `getsockaddr()`+`user_connect()`; frees its internal `sa` copy itself.
**Evidence:**
> usrsctplib/user_socket.c:1964-1979 (definition); usrsctplib/usrsctp.h:1001-1004 (declaration).
> fuzzer/fuzzer_connect.c:281: `usrsctp_set_non_blocking(socket_client, 1);` set earlier.
> fuzzer/fuzzer_connect.c:363-365: `result = usrsctp_connect(socket_client, (struct sockaddr *)&sconn, sizeof(struct sockaddr_conn)); FUZZER_ASSERT(result == 0 || errno == EINPROGRESS);`
**Combination with target:** Immediately after this call, `conn_output()` is invoked synchronously by the stack with the outbound INIT bytes, from which the harness/fuzzer extracts `initiate_tag` to use as `verification_tag` in subsequently-injected INIT-ACK/COOKIE-ACK/DATA packets via `usrsctp_conninput` (fuzzer/fuzzer_connect.c:89, 371, 381, 416, 422, 441).

### usrsctp_listen / usrsctp_accept
**Claim (not exercised by `fuzzer_connect.c`/`fuzzer_fragment.c`, but a valid alternative path)**: `usrsctp_listen(so, backlog)` marks the socket passive (`SCTP_SO_ACCEPTCONN`), must follow `usrsctp_socket`+`usrsctp_bind`. `usrsctp_accept(so, aname, anamelen)` dequeues a completed incoming association (created when a fuzzed INIT is injected via `usrsctp_conninput` and processed by `sctp_handle_init`/`sctp_handle_cookie_echo`) and returns a new `struct socket*` representing that association, or NULL on error/no-pending-connection. This is the server-side counterpart to `usrsctp_connect`; a harness exercising INIT/COOKIE-ECHO handling would use `usrsctp_listen`+`usrsctp_accept` instead of `usrsctp_connect`, then inject COOKIE-ECHO etc. through `usrsctp_conninput` against the listening socket's bound address/port.
**Evidence:**
> usrsctplib/user_socket.c:1539 (`usrsctp_listen` definition), 1761 (`usrsctp_accept` definition); usrsctplib/usrsctp.h:989-996 (declarations).
> programs/ekr_server.c:271-276: `if (usrsctp_listen(s, 1) < 0) {...} if (usrsctp_accept(s, NULL, NULL) == NULL) {...}` — real-world pairing.
> programs/echo_server.c:212-213, programs/discard_server.c:197-198, programs/daytime_server.c:104-109, programs/tsctp.c:738-756: further real `usrsctp_listen`/`usrsctp_accept` pairs, none of them call `usrsctp_conninput` directly (they read from a real UDP socket), confirming `usrsctp_conninput` is specifically the user-space-transport injection point used when the embedder supplies its own I/O (as in `fuzzer_connect.c`/`fuzzer_fragment.c`/`ekr_*` programs), not a requirement for `usrsctp_listen`/`usrsctp_accept` themselves.

### usrsctp_setsockopt
**Claim:** Configures per-socket/per-association options; must be called after `usrsctp_socket` (and some options, e.g. `SCTP_RESET_STREAMS`, are meaningful only once an association exists, i.e. after `usrsctp_connect`/successful handshake). Takes `(so, level, option_name, option_value, option_len)`; returns 0 on success, -1+errno on failure. Options seen driving different paths: `SCTP_INITMSG`, `SO_LINGER`, `SCTP_EVENT` (per event type, looped), `SCTP_RECVRCVINFO`, `SCTP_RECVNXTINFO`, `SCTP_ENABLE_STREAM_RESET`, `SCTP_FRAGMENT_INTERLEAVE`/`SCTP_INTERLEAVING_SUPPORTED`, `SCTP_REUSE_PORT`, `SCTP_NODELAY`, `SCTP_RESET_STREAMS`.
**Evidence:**
> usrsctplib/user_socket.c:2089 (definition); usrsctplib/usrsctp.h:916-921 (declaration).
> fuzzer/fuzzer_connect.c:284-351: repeated `usrsctp_setsockopt(socket_client, IPPROTO_SCTP, <OPT>, ...); FUZZER_ASSERT(result == 0);` sequence, all before `usrsctp_connect`.
> fuzzer/fuzzer_connect.c:401-406: `usrsctp_setsockopt(socket_client, IPPROTO_SCTP, SCTP_RESET_STREAMS, &srs, ...)` gated on `FUZZ_B_INJECT_INIT_ACK && FUZZ_B_INJECT_COOKIE_ACK && FUZZ_B_SEND_STREAM_RESET`, i.e. only after the association is established via injected INIT-ACK/COOKIE-ACK through `usrsctp_conninput`.
**Combination with target:** Options set before the handshake (INITMSG, EVENT, interleaving) change which chunk-type branches are legal/expected when `usrsctp_conninput` later injects packets (e.g. I-DATA only valid if interleaving was enabled); options set after an association is up (RESET_STREAMS) are themselves sometimes triggered as a *reaction* to having injected INIT-ACK/COOKIE-ACK.

### usrsctp_sendv
**Claim:** Queues an outbound user message on an existing (connecting/connected) socket. Needs a valid `struct socket*` from `usrsctp_socket`, typically after `usrsctp_connect`. Returns number of bytes queued, or -1+errno on failure (e.g. `EAGAIN`, `ENOTCONN`); harness does not need to free anything (library copies data internally via mbufs). `flags`/`infotype` (e.g. `SCTP_SENDV_NOINFO`) select the send-info variant used.
**Evidence:**
> usrsctplib/user_socket.c:792 (definition); usrsctplib/usrsctp.h:953-962 (declaration).
> fuzzer/fuzzer_connect.c:390-392: `usrsctp_sendv(socket_client, sendbuffer, strlen(sendbuffer), NULL, 0, NULL, 0, SCTP_SENDV_NOINFO, 0);` called only when both `FUZZ_B_INJECT_INIT_ACK` and `FUZZ_B_INJECT_COOKIE_ACK` flags are set (i.e. after the association is believed established via prior `usrsctp_conninput` injections).
**Combination with target:** Data queued by `usrsctp_sendv` produces outbound DATA chunks (through `conn_output`), whose TSNs are then the subject of subsequently-injected SACK/forward-TSN/stream-reset packets fed through `usrsctp_conninput`, extending coverage of `sctp_process_data`/`sctp_sack_check`.

### usrsctp_recvv
**Claim:** Drains data/notifications delivered by the stack after `usrsctp_conninput` processes inbound DATA/I-DATA chunks. Must be called with a valid socket; typically invoked from inside an upcall registered via `usrsctp_set_upcall`, in a loop while `usrsctp_get_events(sock) & SCTP_EVENT_READ`. Returns the number of bytes read (ssize_t), 0 on EOF/no more data, -1+errno on error; `flags` out-param (`MSG_NOTIFICATION`) distinguishes notifications from data.
**Evidence:**
> usrsctplib/user_socket.c:1066 (definition); usrsctplib/usrsctp.h:964-973 (declaration).
> fuzzer/fuzzer_connect.c:97-133 (`handle_upcall`): loop calling `usrsctp_recvv(sock, buf, BUFFER_SIZE, (struct sockaddr *) &addr, &len, (void *)&rn, &infolen, &infotype, &flags);` checking `flags & MSG_NOTIFICATION` and `n <= 0` to break; `free(buf)` per iteration (caller-allocated buffer, standard malloc/free, not a library resource).
**Combination with target:** This is the primary *result consumer* of `usrsctp_conninput`'s DATA/I-DATA processing — it is what validates that reassembly/ordering produced sane output, making it an important post-call check in the harness.
