## target: uriFreeUriMembersA

### P2.1 Init Sequence
**Claim:** `uriFreeUriMembersA` must be called on a `UriUriA` that is either (a) all-zero (e.g. via `memset`/`calloc`, or produced by `uriFreeUriMembersA`'s own internal `uriResetUri`-style reset helper), or (b) a structure actually populated by one of: `uriParseSingleUriA`/`uriParseSingleUriExA`/`uriParseSingleUriExMmA`, the deprecated `uriParseUriA`/`uriParseUriExA`, `uriCopyUriA`/`uriCopyUriMmA`, `uriMakeOwnerA`/`uriMakeOwnerMmA`, or various `...Mm` setter helpers (`uriAddBaseUriA`, `uriRemoveBaseUriA`, etc.) that fill a `UriUriA` output parameter. Calling it on an uninitialized (garbage) struct is explicitly documented as unsafe.
**Evidence:**
> include/uriparser/Uri.h:353-355: "@remarks Calling on an all-zeros structure (e.g. through memset or calloc) is safe.<br/> Calling on an uninitialized structure is not safe."
> src/UriParse.c:1757-1758 (`ParseUriExMm`): `URI_FUNC(ResetParserStateExceptUri)(state); URI_FUNC(ResetUri)(uri);` — the parser always resets/zeroes the `uri` before filling it, guaranteeing a consistent state for later freeing.
> src/UriCommon.c:76-81 (`ResetUri`): `memset(uri, 0, sizeof(URI_TYPE(Uri)));` — zeroing sets `owner = URI_FALSE` and all pointers NULL.
> fuzz/ParseFuzzer.cpp:25-31: `UriHolder` wraps `memset(...,0,...)` in the constructor and calls `URI_FUNC(FreeUriMembers)` in the destructor, i.e. construct-zero → parse → free is the real-world pattern.

### P2.5 Cleanup Sequence
**Claim:** Inside `FreeUriMembersMm` (called by the target), the free order is: if `uri->owner`: scheme → userInfo → ipFuture (also clears aliased hostText pointers) → hostText (only if not already cleared by ipFuture branch); then unconditionally hostData.ip4, hostData.ip6 (these are always separately malloc'd during parsing, independent of `owner`); then if `uri->owner`: portText; then unconditionally path (`uriFreeUriPathA`, which itself frees each segment's text only if `uri->owner`, and always frees the segment node itself and walks to `next`); then if `uri->owner`: query, fragment. Every freed range has its `first`/`afterLast` set to NULL afterward, and ranges where `first == afterLast` (meaning "empty range pointing at the static `SafeToPointTo` placeholder") are *never* passed to `free()`.
**Evidence:**
> src/UriParse.c:1837-1845 (scheme): `if (uri->owner) { if (uri->scheme.first != NULL) { if (uri->scheme.first != uri->scheme.afterLast) { memory->free(...) } uri->scheme.first = NULL; uri->scheme.afterLast = NULL; } ...`
> src/UriParse.c:1856-1868 (ipFuture / hostText aliasing): "/* NOTE: .hostData.ipFuture holds the very same range pointers as .hostText; we must not free memory twice. */ uri->hostText.first = NULL; uri->hostText.afterLast = NULL; if (uri->hostData.ipFuture.first != uri->hostData.ipFuture.afterLast) { memory->free(...) } ..."
> src/UriParse.c:1880-1890 (ip4/ip6, unconditional on owner): `if (uri->hostData.ip4 != NULL) { memory->free(memory, uri->hostData.ip4); uri->hostData.ip4 = NULL; } if (uri->hostData.ip6 != NULL) { memory->free(memory, uri->hostData.ip6); uri->hostData.ip6 = NULL; }`
> src/UriParse.c:1892-1899 (portText, gated by owner), src/UriParse.c:1902 (`URI_FUNC(FreeUriPath)(uri, memory);`), src/UriParse.c:1904-1922 (query/fragment, gated by owner).
> src/UriCommon.c:83-106 (`FreeUriPath`): walks `pathHead` linked list; `if ((uri->owner == URI_TRUE) && (segWalk->text.first != segWalk->text.afterLast)) { memory->free(...) }`; always `memory->free(memory, segWalk);` on the node itself, then advances to `next`; resets `pathHead`/`pathTail` to NULL.

### P2.7 Co-call Constraints
**Claim:** Pairing is "fill → free": any call that fills or reallocates a `UriUriA` (`uriParseSingleUriA`/`Ex`/`ExMm`, `uriParseUriA`, `uriCopyUriA`/`Mm`, `uriMakeOwnerA`/`Mm`, `uriNormalizeSyntax*`, `uriAddBaseUri*`, `uriRemoveBaseUri*`) must be paired with exactly one eventual `uriFreeUriMembersA`/`uriFreeUriMembersMmA` call on that same struct (never on the same struct twice without re-filling in between — double free). Note: `uriParseSingleUriExMmA` and the internal parser engine already call `FreeUriMembersMm` internally on *failure* (so the caller must NOT free again on failure, only on success) — see P2.9.
**Evidence:**
> src/UriParse.c:1814-1823 (`ParseSingleUriExMm`): on `res != URI_SUCCESS`, internally calls `URI_FUNC(FreeUriMembersMm)(uri, memory);` before returning — the output `uri` is already cleaned up on error; the caller should not call free again (though freeing an already-zeroed struct is itself safe per P2.1's "all-zeros is safe" remark, it is not a strict double-free bug, but is redundant/unnecessary for error paths, and *would* be a bug if the struct were not fully zeroed, e.g. ip4/ip6 set after error in a future code path — current code zeroes via FreeUriMembersMm so re-calling is benign).
> src/UriParse.c:159-164 (`StopSyntax`, internal): `URI_FUNC(FreeUriMembersMm)(state->uri, memory); state->errorPos = errorPos; state->errorCode = URI_ERROR_SYNTAX;` — same "clean on internal failure" pattern for the deprecated streaming `uriParseUriA`.
> fuzz/ParseFuzzer.cpp:96-98,104-108: both `UriHolder`-wrapped `uriParseUriA`/`uriParseSingleUriA` calls `return 0` immediately on failure (relying on RAII `~UriHolder` to call `FreeUriMembers` exactly once, whether parse succeeded or failed).

### P2.10 Behaviour Controls
**Claim:** The dominant behaviour-selecting flag throughout the whole free/parse/copy/normalize surface is `UriUriA.owner` (`UriBool`, set by `uriResetUri`'s memset to `URI_FALSE`, and only ever set to `URI_TRUE` by `uriCopyUriMmA` (UriCopy.c:237) and `uriMakeOwnerMmA`/`NormalizeSyntaxEngine`'s implicit make-owner step (UriNormalize.c:823,847)). When `owner == URI_FALSE` (fresh parse result), `uriFreeUriMembersA` skips freeing scheme/userInfo/host-text/port/path-segment-text/query/fragment (because those pointers alias the caller's original input buffer) but *always* frees `hostData.ip4`/`hostData.ip6` (heap blocks allocated by the parser regardless of ownership) and always frees path-segment list *nodes* (but not their `.text` data unless owner). Other controls: `uriNormalizeSyntaxExA`'s `mask` parameter (bitmask of `URI_NORMALIZE_SCHEME/USER_INFO/HOST/PATH/QUERY/FRAGMENT`) selects which components get normalized/duplicated (and hence which ranges can become owner-owned, affecting later free behaviour); `UriMemoryManager*` parameter on every `...Mm` variant selects malloc/free implementation (NULL ⇒ libc default) used consistently from allocation through to the matching free call.
**Evidence:**
> include/uriparser/Uri.h:156-158: `UriBool absolutePath; ... UriBool owner; /**< Memory owner flag */`
> src/UriParse.c:1837,1848,1857,1871,1893,1904,1914 (owner-gated branches, each `if (uri->owner) {...}` or `if (uri->owner && ...)`)
> src/UriParse.c:1881-1890 (ip4/ip6 freed unconditionally, no owner check)
> src/UriCommon.c:91-94 (`FreeUriPath`): `if ((uri->owner == URI_TRUE) && (segWalk->text.first != segWalk->text.afterLast)) { memory->free(...) }` while the node itself (`segWalk`) is always freed at line 98.
> include/uriparser/Uri.h:712-729 (`NormalizeSyntaxEx`/`NormalizeSyntaxExMm`): "@param mask <b>IN</b>: Normalization mask"; src/UriNormalize.c:817-824: `if ((outMask == NULL) && !uri->owner) { if (!URI_FUNC(MakeOwnerEngine)(uri, &revertMask, memory)) {...} uri->owner = URI_TRUE; }` — plain `uriNormalizeSyntaxA` (mask = `(unsigned int)-1`, i.e. all bits) always ends by making the URI an owner.

### P2.11 Input Expectations
**Claim:** `uriFreeUriMembersA` does not parse/validate text; its "input" is the in-memory `UriUriA` struct shape/invariants established by the producer functions: (1) every `TextRange` is either `{NULL,NULL}` (absent), `{SafeToPointTo, SafeToPointTo}` (present-but-empty, never freed because `first==afterLast`), or a valid `{first,afterLast}` pair with `afterLast >= first`; (2) `hostData.ipFuture` and `hostText` are documented to share identical pointers whenever an IPvFuture host is present, and the free code depends on freeing via the ipFuture branch first then nulling hostText to avoid a double free; (3) `pathHead`/`pathTail` form a NULL-terminated singly linked list via `->next`; (4) `owner` must accurately reflect whether every freeable field is a malloc'd block (TRUE) or aliases external/static memory (FALSE) — mixing (e.g. a struct with `owner=FALSE` but some manually malloc'd field) is explicitly the double-free/leak hazard this routine is sensitive to, per the feature description and the "NOTE" comments embedded in the source.
**Evidence:**
> include/uriparser/Uri.h:84-90 ("Specifies a range of characters... difference is the length"), Uri.h:130-134: "this text range's pointers must be identical to those of UriUriStructA.hostText at all times" (comment directly above `HostData.ipFuture`).
> src/UriParse.c:1858-1859: "/* NOTE: .hostData.ipFuture holds the very same range pointers as .hostText; we must not free memory twice. */"
> src/UriCommon.c:72: `const URI_CHAR * const URI_FUNC(SafeToPointTo) = _UT("X");` — the static placeholder used for empty-but-present ranges, never freed (checked via `first != afterLast` everywhere in the free code).
> src/UriCommon.c:87-103 (`FreeUriPath`): walks `segWalk->next` until NULL, confirming the linked-list termination contract.

## Other entries' call protocol (combined with the target in one harness)

### uriParseSingleUriA / uriParseSingleUriExA / uriParseSingleUriExMmA
**Prerequisite:** None beyond an allocated (stack or heap) `UriUriA` passed as the OUT parameter `uri`. Caller does NOT need to pre-zero it (the engine calls `uriResetUri` internally before writing), but per P2.1 remark, a struct that has never been initialized and is also never passed to Parse is unsafe to free.
**Parameters/flags:**
- `uriParseSingleUriA(UriUriA *uri, const char *text, const char **errorPos)` — `text` must be NUL-terminated; internally computes `afterLast = text + strlen(text)`.
- `uriParseSingleUriExA(UriUriA *uri, const char *first, const char *afterLast, const char **errorPos)` — `afterLast` can be NULL to mean `first+strlen(first)`; otherwise an explicit (possibly non-NUL-terminated) buffer length is used — this is the variant the harness should prefer for arbitrary fuzz bytes (avoids requiring NUL termination / avoids OOB strlen).
- `uriParseSingleUriExMmA` adds a `UriMemoryManager*` (NULL ⇒ default libc).
- `errorPos` is optional (`NULL` allowed); only meaningful when return is `URI_ERROR_SYNTAX`.
**Return:** `int`, `URI_SUCCESS` (0) or an error code (`URI_ERROR_SYNTAX`, `URI_ERROR_NULL`, `URI_ERROR_MALLOC`, ...). Declared `include/uriparser/Uri.h:297,320,343`; defined `src/UriParse.c:1787,1792,1800`.
**What to free:** On failure, the function already calls `uriFreeUriMembersMmA` internally (src/UriParse.c:1820: `if (res != URI_SUCCESS) { ... URI_FUNC(FreeUriMembersMm)(uri, memory); }`) so the `uri` struct is already zeroed/safe; the harness still MAY call `uriFreeUriMembersA(&uri)` again afterward (benign, since the struct is now all-zero per the "all-zeros is safe" contract) but it is not required. On success, the harness MUST eventually call `uriFreeUriMembersA(&uri)` (owner==FALSE state: text ranges alias the input buffer, so the input buffer must outlive the `UriUriA` and must not be freed before `uriFreeUriMembersA`).
**Evidence:** src/UriParse.c:1787-1824; include/uriparser/Uri.h:280-345; fuzz/ParseFuzzer.cpp:104-108 (`UriHolder uriHolder2; if (URI_FUNC(ParseSingleUri)(uriHolder2.get(), uri2.c_str(), nullptr) != URI_SUCCESS) { return 0; }` — RAII destructor still calls FreeUriMembers even on early return).

### uriParseUriA (deprecated, streaming, via UriParserStateA)
**Prerequisite:** Caller must allocate a `UriUriA uri;` and a `UriParserStateA state;`, then set `state.uri = &uri;` BEFORE calling `uriParseUriA(&state, text)`. No separate zeroing needed by caller (internally the engine does `ResetParserStateExceptUri` + `ResetUri`).
**Parameters/flags:** `text` must be a NUL-terminated string (deprecated API computes `text + strlen(text)` as `afterLast`, see `uriParseUriA` wrapper). The lower-level `uriParseUriExA(state, first, afterLast)` takes explicit bounds and is recommended by the deprecation notice but is otherwise equivalent.
**Return:** `int`, 0 (`URI_SUCCESS`) or error code. On syntax error, `state.errorPos`/`state.errorCode` are set (see `StopSyntax`, src/UriParse.c:159-164) and `FreeUriMembersMm` is already invoked internally — so, as above, the `uri` struct is already cleaned on failure.
**What to free:** on success, caller must call `uriFreeUriMembersA(&uri)` (or Mm variant with matching memory manager) after using the parsed `uri`. Declared `include/uriparser/Uri.h:278` (`ParseUri`) / `:259` (`ParseUriEx`); defined `src/UriParse.c:1780` (`ParseUri`) and the internal engine `ParseUriExMm` at `src/UriParse.c:1743-1778`.
**Evidence:** src/UriParse.c:1780-1785, 1743-1778, 159-171 (`StopSyntax`/`StopMalloc` internal early-free helpers); test/test.cpp:66-94 (`testDistinctionHelper`): `UriParserStateA state; UriUriA uri; state.uri = &uri; int res = uriParseUriA(&state, uriText); if (res != URI_SUCCESS) { uriFreeUriMembersA(&uri); return false; } ... uriFreeUriMembersA(&uri);` — demonstrates both the success and failure paths calling `uriFreeUriMembersA` once each (failure path is calling it a second time on an already-cleaned struct, which is safe per P2.1).

### uriCopyUriA / uriCopyUriMmA
**Prerequisite:** `sourceUri` must be a validly-populated `UriUriA*` (already parsed/filled, any owner state); `destUri` must be a pointer to storage for a NEW `UriUriA` — the function calls `uriResetUri(destUri)` internally so pre-zeroing by the caller is not required, but `destUri` must not itself be a struct that still holds live unfreed allocations (those would leak, since `ResetUri` simply memsets without freeing first).
**Parameters/flags:** no behaviour flags; `uriCopyUriMmA` additionally takes `UriMemoryManager*` (NULL ⇒ default). The function always deep-copies every component (scheme/userInfo/hostText/hostData.ip4/ip6/ipFuture/portText/path-segments/query/fragment) using `CopyRangeAsNeeded` which special-cases NULL ranges and empty (`first==afterLast`) ranges to the static `SafeToPointTo` sentinel rather than allocating.
**Return:** `int`, `URI_SUCCESS`, `URI_ERROR_NULL` (if `sourceUri`/`destUri` NULL), or `URI_ERROR_MALLOC` (OOM at any step; on OOM, `PreventLeakageAfterCopy` frees everything copied so far based on an accumulating `revertMask`, leaving `destUri` safe to free or discard without further cleanup — actually since it frees in place and nulls pointers, calling `uriFreeUriMembersA(destUri)` afterward is still safe/idempotent because freed fields are NULLed).
**Postcondition:** on success, `destUri->owner = URI_TRUE` always (src/UriCopy.c:237) — i.e. a copy is unconditionally an owning struct, so `uriFreeUriMembersA(destUri)` will take the "owner" branch and free everything including ip4/ip6 (always freed) and the path list text.
**What to free:** both `sourceUri` and `destUri` independently need their own `uriFreeUriMembersA` call; freeing `destUri` must NOT be skipped just because `sourceUri` is also going to be freed — they own disjoint allocations (copy duplicates, does not alias, except possibly for the static `SafeToPointTo` sentinel which is never freed anyway).
**Evidence:** include/uriparser/Uri.h:654-678; src/UriCopy.c:98-246 (full function body, including `ResetUri` call at line 108, revertMask/PreventLeakageAfterCopy error handling throughout, and `destUri->owner = URI_TRUE;` at line 237).

### uriMakeOwnerA / uriMakeOwnerMmA
**Prerequisite:** `uri` must be an already-populated `UriUriA*` (e.g., freshly returned by `uriParseSingleUriA` with `owner==FALSE`). Safe/no-op to call on an already-owning struct.
**Parameters/flags:** no mask/flags; `uriMakeOwnerMmA` adds `UriMemoryManager*`.
**Return:** `int` — `URI_SUCCESS` immediately if `uri->owner == URI_TRUE` already (src/UriNormalize.c:838-840: `if (uri->owner == URI_TRUE) { return URI_SUCCESS; }`), else attempts `MakeOwnerEngine` to duplicate every range/host-data block that currently aliases external memory; on failure returns `URI_ERROR_MALLOC` after `PreventLeakage` reverts partial allocations using a `revertMask`; `URI_ERROR_NULL` if `uri == NULL`.
**Postcondition:** on success sets `uri->owner = URI_TRUE` (src/UriNormalize.c:847).
**What to free:** same `uri` object must later go through exactly one `uriFreeUriMembersA(uri)` call — now with owner==TRUE, so every component (including ip4/ip6, already always freed) gets its text fields freed too.
**Evidence:** include/uriparser/Uri.h:1100-1127; src/UriNormalize.c:829-854 (`MakeOwnerMm`/`MakeOwner`); test/test.cpp:2463-2488 (`MakeOwnerSuite.MakeOwner`: `EXPECT_EQ(uriMakeOwnerA(&uri), URI_SUCCESS);` after a parse, followed eventually by `uriFreeUriMembersA`).

### uriNormalizeSyntaxA (and NormalizeSyntaxEx/ExMm/MaskRequiredEx)
**Prerequisite:** `uri` must already be a populated `UriUriA*` (parsed result). No other setup.
**Parameters/flags:** `uriNormalizeSyntaxA(uri)` is a convenience wrapper calling `uriNormalizeSyntaxExA(uri, (unsigned int)-1)` (src/UriNormalize.c:512-514), i.e. normalizes ALL components. `uriNormalizeSyntaxExA(uri, mask)` accepts an explicit bitmask (`URI_NORMALIZE_SCHEME`, `_USER_INFO`, `_HOST`, `_PATH`, `_QUERY`, `_FRAGMENT`, or the aggregate `URI_NORMALIZED` meaning "nothing to do") to select which components get case-folded/percent-decoded-refolded/dot-segment-removed. `uriNormalizeSyntaxMaskRequiredExA(uri, &outMask)` is a read-only inspector (no `memory` needed, no mutation) that computes which bits WOULD need normalizing — typical pre-check before calling the mutating variant, as seen in the project's own fuzzer.
**Return:** `int`, `URI_SUCCESS`/`URI_ERROR_NULL`/`URI_ERROR_MALLOC`. On `URI_ERROR_MALLOC`, partial work is reverted via `PreventLeakage(uri, revertMask, memory)` (src/UriNormalize.c various `return URI_ERROR_MALLOC;` sites), leaving `uri` in a safe-to-free state (freed fields NULLed).
**Side effect relevant to the target:** When called with the full/default mask (`uriNormalizeSyntaxA`) and `uri->owner == URI_FALSE`, after normalizing in-place-able components, the engine additionally runs `MakeOwnerEngine` and sets `uri->owner = URI_TRUE` (src/UriNormalize.c:817-824) — so after `uriNormalizeSyntaxA`, the struct always becomes an owner, changing which branches `uriFreeUriMembersA` will take compared to directly freeing a freshly-parsed (non-owner) struct.
**What to free:** same `uri`, still exactly one later call to `uriFreeUriMembersA(uri)` — now taking the owner==TRUE path.
**Evidence:** include/uriparser/Uri.h:680-766 (declarations + mask semantics); src/UriNormalize.c:502-514, 576-827 (`NormalizeSyntaxEngine`, owner-gated branches lines 621-815, final `MakeOwnerEngine` call lines 817-824); fuzz/ParseFuzzer.cpp:112-114 (`URI_FUNC(NormalizeSyntaxMaskRequiredEx)(state1.uri, &mask); URI_FUNC(NormalizeSyntax)(state1.uri);` immediately followed later by the `UriHolder` destructor's `FreeUriMembers` call).

### How these combine with the target in one harness (evidence from the project's own fuzzers)
